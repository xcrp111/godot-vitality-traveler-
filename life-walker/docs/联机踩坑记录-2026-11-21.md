## 一、目标与方案选择

目标：农场好友社交——加好友、访问好友农场、帮忙浇水、偷菜，好友之间数据要真实互通。

| 方案 | 结论 |
|---|---|
| A. 纯 `clientCloud`（不改架构） | ❌ 只能读写**自己**的数据，读不到好友农场；写别人的数据更不可能 |
| B. 开 `multiplayer` + `serverCloud` | ✅ 采用。服务端可读写任意 uid，能跨玩家、能防作弊 |
| C. 真实时联机（同屏互访） | ❌ 肉鸽战斗完全没为多人设计，等于重做 |

**关键取舍**：服务端**只做数据服务，不参与战斗**。战斗仍在客户端跑（现有代码零改动），
所以这不是"把游戏改成权威服务器"，理论上 1～2 周能做完。**但目前卡在通信层，没走通。**

## 三、已经定位并修复的问题（按发现顺序）

### 1. `SendRemoteEvent` 第三参必须是 `VariantMap`
**症状**：每帧 `UPDATE ERROR: argument #2 is 'string'; 'const StringHash' expected`，
整个 `HandleUpdate` 每帧中断（游戏逻辑卡死、农场同步一次都没成功）。
**原因**：直接把 JSON 字符串当 payload 传。
**修法**：`local vm = VariantMap(); vm["Data"] = Variant(json)`，见 `FarmShared.MakePayload`。

### 2. 客户端调用了不存在的函数，且被 `pcall` 吞掉
`main.lua` 里写的是 `FarmClient.Subscribe()`，而实际函数名是 `RegisterEvents()`。
外面包了 `pcall`，错误完全静默 → 客户端**从未订阅过**任何回包事件。
**教训**：这类初始化调用不要用裸 `pcall` 包住，至少打印错误。

### 3. 全局回调 `FarmClientOnPacket` 只被引用、没被定义
`SubscribeToEvent(name, "FarmClientOnPacket")` 要求回调是**全局函数**，
当时压根没定义 → 引擎报 `Could not find Lua function`。

### 4. 服务端入口用 `main.lua` 时可能整体加载失败
`main.lua` 顶部 `require` 了一堆渲染模块（UI / SceneUI / FarmArt / Combat），
服务端是 headless 无渲染进程，加载期就报错 → 整个服务端脚本没跑起来 → 客户端永远等不到回包。
**修法**：新增 `scripts/server_main.lua`（40 行，只加载 `network.FarmServer`）。

> ⚠️ **踩坑**：构建时给 `maker_build` 传 `entry_client` / `entry_server` 两个参数后，
> 引擎**回退到了内置模板脚本**（屏幕上出现 "Welcome to UrhoX!"，完全不可玩）。
> 已回退成单一入口 `entry: main.lua`。**这条目前没有确认的正确用法，接手时请谨慎。**

### 5. 联机模式下所有文字消失（已验证修复思路）
**症状**：联机客户端里所有 UI 文字不见了，但面板、角色、按钮框都正常。
**定位手段**：在左下角画 5 个诊断点（颜色编码），截图读出：
`字体创建失败 / nvgText 未被接管 / 文本宽度 0 / 上下文一致 / 字号正常`。
**结论**：`nvgCreateFont` 在 **Boot 阶段**（启动瞬间）返回 -1，字体的图集纹理还没就绪。
**修法**：把建字体挪到 **渲染阶段**（`HandleRender` 里每 0.5 秒重试一次），恢复。

### 6. 大厅用 `urhox-libs/UI` 会和游戏抢 NanoVG 上下文
最初大厅用 `urhox-libs/UI` 搭，进游戏后文字全丢（同问题 5 的表现）。
**修法**：大厅改用项目自己的 NanoVG 界面（`UI.lua`），不引第三方 UI 库。

## 四、目前卡在哪里（**核心未解问题**）

### 现象
客户端每秒发一次同步请求，服务端**始终没有回包**：

```
[FarmNet] 已发送同步请求 sent=true tries=1 … tries=19
（没有任何回包日志）
```

### 已排除
- ✅ 客户端连接存在：`network:GetServerConnection()` 非空，`SendRemoteEvent` 不再报错
- ✅ 客户端事件已注册并订阅（本地日志确认 6 行 `[FarmNet] ...`）
- ✅ 服务端数据层逻辑正确（`DevFarmStore` / `DevFarmNet` 本地全链路 50 项全过）
- ✅ 服务端入口文件单独 headless 跑通：`[Farm] 服务端已启动（serverCloud=true）`
- ❌ **无法确认联机时服务端脚本到底有没有被加载**——手机上拿不到服务端日志

### 已切换但未验证的方案：云变量轮询
绕开远程事件，用云变量当"信箱"：

```
客户端写 clientCloud["farm_req"]  →  服务端每 0.5s 用 serverCloud:Get(uid,"farm_req") 轮询
读 clientCloud["farm_resp"]       ←  服务端 serverCloud:Set(uid,"farm_resp", 回包)
```

代码已实现（`FarmClient.EnableCloudTransport` / `FarmServer.Poll`），
但因为 `multiplayer` 已关闭，**还没有真正在真机上验证过**。
另外发现过一个自己引入的 bug：每秒的重试把云传输覆盖回远程事件，
已修（`TryWireFarmSync` 里判断 `FarmClient.cloudMode`）。

## 五、接手建议（按优先级）

1. **先拿到服务端日志**（最重要）
   - `taptap-maker console open` 打开 Maker 控制台，看远端 `server_*.log`
   - 或者在服务端脚本里把关键状态写进 `serverCloud`，客户端读出来显示（已实现「服务端自检」：`FarmClient.ReadServerDiag` + 好友界面那行）
2. **确认服务端脚本是否真的被加载**
   - 服务端启动时会打印 `[server] 服务端脚本加载开始` / `[Farm] 服务端已启动`
   - 如果日志里没有 → 问题在构建/入口配置，不在业务代码
3. **验证远程事件的最小闭环**：先做一个 `Ping`/`Pong`
   - 客户端 `SendRemoteEvent("Ping")`，服务端收到后 `SendRemoteEvent("Pong")`
   - 能通，再往上套农场的 8 个事件；不通，说明是环境/配置问题，不要改业务代码
4. 远程事件确认不通后，再验证云变量轮询方案（代码已就绪，只需打开 `multiplayer` 并跑一次）

## 七、如何切回联机继续调试

1. `.project/settings.json` → `@runtime.multiplayer` 改成：
   ```json
   { "enabled": true, "lobby_runtime": "scripts/lobby_runtime.lua" }
   ```
2. 构建**只传** `entry: "main.lua"`（不要传 `entry_client` / `entry_server`，见问题 4）
3. 进游戏后打开「好友」界面，看顶部状态与「服务端自检」那一行
4. 有任何异常，用游戏内 `⋯` → 反馈 提交，然后 `get_debug_feedbacks` 拉日志（只含客户端日志）
