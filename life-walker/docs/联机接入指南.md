# 联机接入指南（给公会 / 后续模块的同学）

> 面向：要在《生命行者》里加联机玩法（公会、好友、交易…）的同学。
> 现状：项目已开启 `multiplayer`，联机底座（身份 / 连接 / 请求响应 / 云端读写）已经搭好，
> 新模块只要**注册事件 + 写数据层 + 挂 UI**，不用再碰网络底层。

---

## 一、整体结构

```
大厅（scripts/lobby_runtime.lua）
  ├─ 单机开始  → 直接跑现有游戏（离线，不需要网络）
  └─ 联机进入  → CreateRoom → StartGame → 连服务器

进服后：
  客户端（main.lua 普通分支）                 服务端（main.lua 的 IsServerMode 分支）
  ├─ 游戏本体（战斗/农场/UI）                 ├─ 只跑数据服务，不跑战斗
  ├─ network/NetCore.lua  公共底座            ├─ network/NetCore.lua  同一个文件
  ├─ network/FarmClient.lua 农场客户端        ├─ network/FarmServer.lua 农场服务端
  └─ 你的 GuildClient.lua                     └─ 你的 GuildServer.lua

  ↑ 两者之间用「远程事件」通信，事件名约定 `模块.动作`，如 farm.sync / guild.apply
```

**核心取舍**：战斗和大部分玩法仍跑在客户端，服务端只保存**跨玩家共享的数据**（农场、公会…）。
所以加联机功能不需要把整个游戏改成服务器权威。

## 二、目录与职责

| 文件 | 作用 | 谁维护 |
|---|---|---|
| `scripts/network/NetCore.lua` | 公共底座：身份码、连接状态、请求-响应（seq 配对）、服务端路由、云端 KV 封装、状态文案 | 公共，**改动前先跟 hu 说一声** |
| `scripts/network/FarmShared.lua` | 农场事件名 / 云变量 key / 编解码 | 农场 |
| `scripts/network/FarmServer.lua` | 农场服务端：uid 维度文档读写、浇水/偷菜/好友的权威裁决 | 农场 |
| `scripts/network/FarmClient.lua` | 农场客户端：同步、动作上行、回包分发、离线回退 | 农场 |
| `scripts/lobby_runtime.lua` | 自定义大厅（单机 / 联机两个入口） | 公共 |
| `scripts/FarmStore.lua` | 农场纯逻辑（双端共用、可单测） | 农场 |

**建议公会也照这个拆**：`GuildStore.lua`（纯逻辑）+ `network/GuildShared.lua` + `network/GuildServer.lua` + `network/GuildClient.lua`。

## 三、NetCore 用法（公共能力）

```lua
local NetCore = require "network.NetCore"

-- 身份
NetCore.PlayerCode("1000822123456")   --> "123456"（给玩家看的短码/搜索用）
NetCore.SetIdentity(uid, nickname)    -- 进服后设一次
NetCore.StatusText()                  --> "● 已连服务器　阿茶" / "○ 离线（本地模拟）"
NetCore.OnIdentity(function(uid, name) ... end)

-- 客户端发请求（自动 seq 配对，回包进 cb）
NetCore.Request("guild.apply", { guildId = 7 }, function(resp)
    if resp.ok then ... else UI.SetToast(resp.msg or "失败") end
end)

-- 客户端订阅服务端主动推送
NetCore.On("guild.notify", function(p) ... end)

-- 服务端注册路由（handler 里用 reply 回包）
NetCore.ServerRoute("guild.apply", function(uid, body, reply)
    reply({ ok = true, msg = "已申请" })
end)

-- 服务端云端 KV（自动 JSON 编解码）
NetCore.CloudGet(uid, "guild_doc", function(doc) ... end)
NetCore.CloudSet(uid, "guild_doc", doc)
```

### 回包约定

```lua
{ ok = true|false, code = "offline"|"no_route"|..., msg = "给玩家看的话", ...业务字段 }
```
`seq` 由 NetCore 自动补，业务代码不用管。

## 四、加一个模块的完整步骤（以公会为例）

### 1) 数据层（纯逻辑，双端共用，能单测）

```lua
-- scripts/GuildStore.lua
local GuildStore = {}
GuildStore.NewDoc = function(gid, name, now) ... end
GuildStore.Apply   = function(doc, uid, now) ... end   -- 返回 ok, msg
GuildStore.Snapshot= function(doc) ... end             -- 对外可见字段（别下发隐私数据）
return GuildStore
```

### 2) 事件名与 key

```lua
-- scripts/network/GuildShared.lua
local GuildShared = {}
GuildShared.KEY = "guild_doc"          -- serverCloud 里的 key，一个模块一个，别和 farm_doc 撞
GuildShared.EVENTS = {
    APPLY = "guild.apply",
    LIST  = "guild.list",
    RESULT = "guild.result",
}
return GuildShared
```

### 3) 服务端

```lua
-- scripts/network/GuildServer.lua
local NetCore = require "network.NetCore"
local GuildStore = require "GuildStore"
local Shared = require "network.GuildShared"

function GuildServer.Start()
    NetCore.ServerRoute(Shared.EVENTS.APPLY, function(uid, body, reply)
        NetCore.CloudGet(body.gid, Shared.KEY, function(doc)
            doc = GuildStore.Ensure(doc) or GuildStore.NewDoc(body.gid, body.name, os.time())
            local ok, msg = GuildStore.Apply(doc, uid, os.time())
            NetCore.CloudSet(body.gid, Shared.KEY, doc, function(saved)
                reply({ ok = ok and saved, msg = msg })
            end)
        end)
    end)
end
```
服务端入口已在 `main.lua` 的 `IsServerMode()` 分支里，加一行 `GuildServer.Start()` 即可。

### 4) 客户端

```lua
-- scripts/network/GuildClient.lua
local NetCore = require "network.NetCore"
local Shared = require "network.GuildShared"

function GuildClient.Apply(gid, cb)
    NetCore.Request(Shared.EVENTS.APPLY, { gid = gid }, cb)
end
```
远程事件注册 + `ClientConnected` 事件里已经在做连接装配（见 `main.lua` 的 `HandleFarmClientConnected`），
公会照抄一份或直接在同一个回调里初始化。

### 5) UI

沿用 `urhox-libs/UI` 或项目现有的 NanoVG 自绘（参考 `scripts/FriendUI.lua`：列表 / 搜索 / 请求 三个视图 + 软键盘）。

## 五、身份与好友（已实现，可直接复用）

- **玩家 ID**：`NetCore.uid`（TapTap 用户 id，字符串）
- **展示短码**：`NetCore.PlayerCode(uid)` → 6 位字母数字，可给玩家看 / 口头分享
- **昵称**：`GetUserNickname({userIds={uid}, onSuccess=..., onError=...})`，服务端也已有接口
- **搜索**：服务端 `FarmServer.HandleFriendSearch` 里按 `uid` 精确 / 名字前缀匹配，公会搜人可复用同一套匹配规则（`FarmStore.MatchQuery`）

## 六、测试（**不用真连服务器**）

所有网络逻辑都设计成可用"假传输"直连服务端：

```lua
-- dev/DevXxx.lua
local NetCore = require "network.NetCore"
NetCore.ServerRoute("demo.echo", function(uid, body, reply)
    reply({ ok = true, echo = body.text })
end)
NetCore.SetTransport({
    send = function(event, payload)
        NetCore.ServerDispatch(payload.__uid or "u1", event, payload, function(resp)
            NetCore.ClientDispatch(event, resp)
        end)
    end,
})
NetCore.Request("demo.echo", { text = "hi" }, function(r) print(r.echo) end)
```

参考现成例子：

- `dev/DevNetCore.lua`：底座本身（16 项）
- `dev/DevFarmStore.lua`：纯逻辑（30 项）
- `dev/DevFarmServer.lua`：服务端文档/同步包（12 项）
- `dev/DevFarmNet.lua`：客户端↔服务端全链路（16 项）
- `dev/DevLobby.lua`：大厅脚本自检（3 项）

运行方式：

```bash
./.cli/UrhoXRuntime.exe dev/DevFarmNet.lua -tapcode_dir=. -tool_mode -graphicsheadless -validate
```

## 七、上线前的检查清单

- [ ] 事件名在 `FarmShared`/`GuildShared` 里登记，服务端 `network:RegisterRemoteEvent` 已注册
- [ ] 服务端 handler 里 uid 从连接身份取（`connection.identity["user_id"]`），**不要信客户端传的 uid**
- [ ] 回包走 `reply(...)`，别自己拼 `SendRemoteEvent`
- [ ] 云端 key 一个模块一个（`farm_doc` / `guild_doc` …）
- [ ] 下发给别人的数据只放 `Snapshot`，别把种子、果实、钱包等隐私字段一起发出去
- [ ] 离线分支要有兜底（`NetCore.online == false` 时 UI 给提示或退回本地模拟）
- [ ] 加一个 `dev/DevXxx.lua` 回归，全绿再构建

## 八、已知坑（踩过的）

1. **回包必须带 seq**：否则客户端配不上回调。NetCore 已统一补，自己写底层时注意。
2. **事件没注册就发**：`network:RegisterRemoteEvent` 漏注册会静默丢包。
3. **服务端 handler 抛错**：会被 NetCore 兜成 `server_error` 回给客户端，但日志里要能查到。
4. **本地 `-validate` 不跑大厅**：本机 headless 只能验证普通单机分支，大厅/联机流程要在真机（扫码）验。
5. **改 `NetCore.lua` 会影响农场**：如果要改，先跑 `dev/DevNetCore.lua` + `dev/DevFarmNet.lua`。
